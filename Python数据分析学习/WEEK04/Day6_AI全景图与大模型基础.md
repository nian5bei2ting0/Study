## 三、传统 ML vs 深度学习 vs LLM

| 维度 | 传统 ML（sklearn） | 深度学习 | LLM |
|------|-------------------|---------|-----|
| 数据量 | 中小（百~万） | 大（万~亿） | 极大（千亿 token） |

## 四、大模型（LLM）基础

### 1. 什么是 LLM

**大语言模型**：用海量文本训练的超大神经网络，能理解和生成人类语言。

核心能力：
- **理解**：读懂自然语言
- **生成**：续写、回答、翻译、改写
- **推理**：通过思维链做逻辑推导
- **工具调用**：调用外部 API、代码

### 2. LLM 怎么训练的（简化版）

```
1. 预训练（Pretrain）：海量文本，学"接龙"——给上文预测下文
   → 学会语言规律和世界知识
2. 指令微调（SFT）：用"指令-回答"对，学听人话
   → 学会按指令做事
3. RLHF（人类反馈强化学习）：用人类偏好打分优化
   → 学会"好"的回答
```

### 3. Transformer 架构（了解即可）

LLM 的核心架构，2017 年 Google 提出。关键机制：**自注意力（Self-Attention）**——让每个词"看到"句子中所有其他词，决定关注谁。

> 不需要懂细节，只要知道：**Transformer 让模型能处理长序列并捕捉远距离依赖**，这是 LLM 强大的基础。

## 五、Token：LLM 的最小单位

LLM 不直接处理字符，而是把文本切成 **token**（子词单元）。

```
"Hello world" → ["Hello", " world"]  → 2 个 token
"你好世界"   → ["你","好","世","界"]  → 4 个 token（中文常 1 字 1 token）
```

### 为什么重要
- **计费按 token**：输入 + 输出都算
- **上下文窗口按 token**：模型一次能"看到"多少 token
- **生成速度按 token/s**：每秒生成多少 token

### 上下文窗口

| 模型 | 上下文 |
|------|-------|
| 早期 GPT-3 | 2K |
| GPT-4 | 8K~128K |
| Claude 3 | 200K |
| Gemini 1.5 | 1M+ |

> 上下文越大，能处理的文档越长，但**越长越贵越慢**，且注意力会衰减。

## 六、LLM 的能力边界（重要！）

### LLM 擅长

- 文本理解、改写、翻译
- 代码生成、解释
- 头脑风暴、写作
- 知识问答（常识、教科书知识）
- 结构化输出（JSON、表格）

### LLM 不擅长 / 会出错

- **数学计算**：会算错，需调用计算器/代码
- **实时信息**：训练数据有截止日期
- **精确事实**：会"幻觉"（编造看似合理但错误的内容）
- **长文档精确细节**：注意力衰减
- **结构化数据建模**：表格数据分类/回归仍需传统 ML

### 幻觉（Hallucination）

LLM 会**自信地编造不存在的事实**。原因：它在做概率续写，不是查数据库。

应对：
- 让模型"不知道就说不知道"
- 提供参考资料（RAG）
- 关键事实人工核对
- 让模型分步推理（思维链）

## 七、Embedding：LLM 的向量表示

LLM 把每个 token/句子变成一个高维向量（如 1536 维），**语义相近的向量也相近**。

```python
# 概念示意（实际需调 API）
# "猫" → [0.12, -0.34, ...]  1536 维
# "狗" → [0.11, -0.33, ...]  与"猫"很近
# "汽车" → [0.78, 0.21, ...]  与"猫"很远
```

应用：
- **语义搜索**：找"意思相近"而非"字面相同"
- **RAG**：检索知识库喂给 LLM
- **聚类/分类**：把文本转向量后用传统 ML

> 这是 LLM 与传统 ML 的**桥梁**——用 LLM 提特征，用 sklearn 建模。

## 十、AI 时代的学习策略

1. **会用大模型 > 会写算法**：90% 的工作用 API 解决，不必从零实现算法。
2. **理解原理 > 死记 API**：知道 LLM 为什么会幻觉，才知道怎么防。
3. **传统 ML 仍重要**：结构化数据、可解释性要求高的场景仍是传统 ML 强项。
4. **提示词工程是核心技能**：明天详讲。
5. **持续学习**：LLM 迭代极快，关注新模型新能力。
