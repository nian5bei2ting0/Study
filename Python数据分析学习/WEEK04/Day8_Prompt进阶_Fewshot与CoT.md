## 一、为什么需要进阶技术

Day7 的 CRISPE 是"通用骨架"，但遇到下面两类任务会力不从心：

| 任务类型 | 难点 | 解决方案 |
|---------|------|---------|
| 输出格式/风格难描述 | 模型猜不准 | **Few-shot**：给示例让它照着学 |
| 多步推理/数学/逻辑 | 一步到位易错 | **CoT**：让它分步思考 |

> Few-shot 解决"输出长什么样"，CoT 解决"怎么想清楚"。两者可单独用，也可组合。

# 第一部分：Few-shot 少样本提示

## 二、什么是 Few-shot

**Few-shot**：在提示词里给模型若干个"输入→输出"示例，让它照着示例的模式处理新输入。

按示例数量分：

| 名称 | 示例数 | 适用 |
|------|--------|------|
| Zero-shot | 0 | 简单任务、模型已熟悉 |
| One-shot | 1 | 演示格式 |
| Few-shot | 2~5 | 复杂模式、稳定输出 |
| Many-shot | 10+ | 极复杂模式（受上下文限制） |

> 经验：**3~5 个示例是性价比最高的区间**。太多浪费 token，太少学不准。

## 三、Few-shot 标准结构

```
[任务说明]

示例1：
输入：{输入1}
输出：{输出1}

示例2：
输入：{输入2}
输出：{输出2}

现在请处理：
输入：{真实输入}
输出：
```

模型会照着"输入→输出"的模式续写。

## 四、Few-shot 实战示例

### 示例 1：情感分类

```

评论：这个手机续航强，拍照清晰。

评论：包装破损，退货麻烦。
分类：负面

评论：手机收到了，还没拆封。
分类：中性

评论：屏幕不错但发热严重。
分类：
```

模型输出：`负面`（或`中性`，看它如何权衡）

### 示例 2：信息抽取为 JSON

```
从用户评论提取字段，按 JSON 输出，找不到填 null。

评论：我买的红色 iPhone 15 256G，3 天就到了。
输出：{"product":"iPhone 15","color":"红色","storage":"256G","delivery_days":3}

评论：耳机一周就坏了，蓝色那款。
输出：{"product":"耳机","color":"蓝色","storage":null,"delivery_days":null}

评论：MacBook Pro 14 寸银色，物流 5 天。
输出：
```

### 示例 3：风格模仿

```

正式：本产品不支持退换货。

正式：会议将于下午两点准时开始。

```

模型输出：`下午两点开会，别迟到。`

## 五、Few-shot 的 5 个关键技巧

### 1. 示例要"覆盖分布"

不要 3 个示例都是正面，模型会偏向总输出正面。

- **好**：正/负/中各 1 个
- **坏**：3 个都是正面，第 4 个真实输入是负面 → 模型可能仍输出正面

### 2. 示例顺序影响输出

LLM 有"近因效应"——**最后那个示例影响最大**。把和真实输入最相似的示例放最后。

### 3. 示例要"无矛盾"

所有示例的输出格式必须严格一致（字段名、顺序、引号风格），否则模型会混乱。

### 4. 加"反例"教边界

```
评论：价格 199 元。
分类：中性   ← 这是事实陈述，不是评价

评论：价格太贵了。
分类：负面   ← 这才是评价
```

反例帮模型理解"什么不算正面/负面"。

### 5. 示例数量动态调整

- 输出简单（如分类）：2~3 个够
- 输出复杂（如 JSON 多字段）：4~5 个
- 模式罕见（如特殊格式）：5+ 个

## 六、Few-shot 进阶变体

### 1. K-shot + 格式锚定

在示例后加一个"半截输出"引导：

```
输入：屏幕不错但发热严重。
输出：{"sentiment":"
```

模型被迫从 `{"sentiment":"` 开始续写，格式更稳。

### 2. 示例 + 规则结合

```
规则：只输出类别名，不要解释。若评论含"但"，倾向负面。
示例1：...
示例2：...
```

规则补示例覆盖不到的边界。

### 3. 动态 Few-shot（RAG 检索示例）

对每个新输入，**从示例库检索最相似的 3 个**作为 few-shot。比固定示例更准。

## 七、Few-shot 的局限

- **占用上下文**：示例越多，留给真实任务的窗口越小
- **不解决推理**：复杂推理任务 few-shot 也救不了，需要 CoT
- **示例偏差**：示例选不好会带偏模型
- **不改变能力**：模型不会的，给示例也学不会（如精确数学）

# 第二部分：CoT 思维链

## 八、什么是 CoT

**CoT（Chain-of-Thought）**：让 LLM 把推理过程"写出来"，而不是直接给答案。

**直接答**：
```
问题：一个商品原价 200，打 8 折，再用 30 元券，最后多少钱？
答：130 元
```
模型可能算错。

**CoT**：
```
问题：一个商品原价 200，打 8 折，再用 30 元券，最后多少钱？
请一步一步思考。
答：
1. 原价 200 元
2. 打 8 折：200 × 0.8 = 160 元
3. 用 30 元券：160 - 30 = 130 元
所以最后 130 元。
```

分步写出来 → 每步可验证 → 准确率大幅提升。

> **核心原理**：LLM 是"续写机器"，把中间步骤写出来等于给自己创造更好的上下文，后续步骤基于已写出的正确中间结果，错误率下降。

## 九、CoT 的两种触发方式

### 1. Zero-shot CoT（最简单）

在问题后加一句魔法咒语：

```
问题：{问题}
让我们一步一步思考。
```

或英文：`Let's think step by step.`

> 这一句就能让多数模型进入分步推理模式，**零成本试一试**。

### 2. Few-shot CoT（更稳）

给带推理过程的示例：

```
问题：小明有 5 个苹果，给小红 2 个，又买了 3 个，现在几个？
推理：5 - 2 = 3，3 + 3 = 6
答案：6

问题：一个班 40 人，男生比女生多 4 人，女生几人？
推理：女生 = (40 - 4) / 2 = 18
答案：18

问题：火车 2 小时行 240 公里，5 小时行多少公里？
推理：
```

模型会照着写推理再给答案。

## 十、CoT 实战示例

### 示例 1：数学应用题

```
问题：一件衣服先涨价 20%，再降价 20%，相比原价是涨了还是降了？变化百分之几？
请一步一步思考。

解：
1. 设原价 100 元
2. 涨价 20%：100 × 1.2 = 120 元
3. 降价 20%：120 × 0.8 = 96 元
4. 96 < 100，所以降了
5. 降幅 = (100 - 96) / 100 = 4%
答：降了 4%。
```

### 示例 2：逻辑推理

```
问题：A 比 B 高，C 比 B 矮，D 比 A 高，谁最高？
请一步一步推理。

推理：
1. A > B（A 比 B 高）
2. C < B（C 比 B 矮）
3. D > A（D 比 A 高）
4. 综合：D > A > B > C
答：D 最高。
```

### 示例 3：条件判断

```
问题：某商品满 200 减 30，满 300 减 50，可叠加吗？不可。买 280 元实付多少？
请一步一步思考。

推理：
1. 满 200 减 30 适用，满 300 减 50 不适用（280 < 300）
2. 两优惠不可叠加，取一个：用满 200 减 30
3. 实付 = 280 - 30 = 250
答：250 元。
```

## 十一、CoT 的 4 个进阶技巧

### 1. Self-Consistency 自洽性（提精度）

让模型对同一问题**生成多条推理路径**，取多数答案投票：

```
对下面问题生成 3 种不同推理路径，最后投票选出现最多的答案。
问题：...
```

复杂推理任务准确率能再提 5~15%。

### 2. 分解 + CoT

把大问题拆成小问题，每个小问题单独 CoT：

```
任务：分析这份合同的风险。
第1步：提取所有条款（CoT 列出）
第2步：对每条条款评估风险（CoT 逐条分析）
第3步：汇总高风险条款（CoT 综合）
```

### 3. 自检 CoT

推理完让它自查：

```
推理完成后请自检：
1. 每步计算是否正确？
2. 中间结论是否矛盾？
3. 最终答案是否合理？
如有错误请修正。
```

### 4. 结构化 CoT

强制输出结构，便于程序解析：

```
按以下 JSON 格式输出：
{
  "steps": ["步骤1...", "步骤2...", ...],
  "answer": "最终答案"
}
```

## 十二、CoT 的适用与不适用

### 适用

- 数学应用题
- 多步逻辑推理
- 条件判断（满减、规则套用）
- 因果分析
- 规划类任务（旅行、项目分解）

### 不适用（甚至有害）

- 简单事实问答（"中国首都" → 直接答，CoT 反而绕弯）
- 创意写作（CoT 会破坏发散性）
- 已熟练任务（模型已会，CoT 浪费 token）
- 实时对话（CoT 输出长，体验差）

> **CoT 不是万能药**，简单任务用了反而慢且贵。

# 第三部分：Few-shot + CoT 组合

## 十三、组合模板

```
任务：{任务说明}

示例1：
问题：{问题1}
推理：{分步推理1}
答案：{答案1}

示例2：
问题：{问题2}
推理：{分步推理2}
答案：{答案2}

现在请处理：
问题：{真实问题}
推理：
```

模型会先写推理再给答案，且格式与示例一致。

## 十四、组合实战：复杂规则套用

```
任务：根据优惠规则计算实付金额。
规则：满 200 减 30，满 300 减 50，不可叠加；会员再 9 折，与满减可叠加。

示例1：
问题：订单 250 元，是会员。
推理：
1. 满 200 减 30 适用，满 300 不适用
2. 取满 200 减 30：250 - 30 = 220
3. 会员 9 折：220 × 0.9 = 198
答案：198 元

示例2：
问题：订单 350 元，非会员。
推理：
1. 满 300 减 50 适用（优于满 200 减 30）
2. 350 - 50 = 300
3. 非会员不打折
答案：300 元

问题：订单 180 元，是会员。
推理：
```

模型输出：
```
1. 满 200 不满足，满 300 不满足，无满减
2. 原价 180
3. 会员 9 折：180 × 0.9 = 162
答案：162 元
```
