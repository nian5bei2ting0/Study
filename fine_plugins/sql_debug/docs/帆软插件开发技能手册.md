# 帆软 FineReport 11 插件开发技能手册

> 基于本仓库 **数据集调试助手**（`com.fr.plugin.report.debug.assistant`）实战总结，适用于下次开发其他 FR 11.x 插件时快速选型、少踩坑。  
> 配套：`plugin.xml`、`DEV_AGENT_PROMPT.md`、官方参考 `_ref_plugin/com/fr/plugin/debugging/assistant/`。

---

## 1. 先想清楚：插件要挂在哪

| 目标 | 用哪个扩展点 | 典型入口 |
|------|-------------|----------|
| 决策平台「管理系统」里一页配置 | `extra-decision` 三件套 | 侧栏菜单 + 配置表单 |
| 报表预览页加按钮/浮层/脚本 | `extra-report` JS/CSS Handler | 预览 HTML 注入 |
| 自定义 HTTP（预览/移动端可调） | `extra-core` → `WebService` | `ReportServer?op=xxx&cmd=yyy` |
| 文案/权限树名称 | `extra-core` → `LocaleFinder` + `plugin-xml-i18n` | i18n properties |
| 功能点/埋点 | `function-recorder` | 决策选项类 |

**决策页必须三件套同时注册**（缺一常见现象：权限树有、侧栏无）：

```xml
<extra-decision>
    <SystemOptionProvider class="..."/>      <!-- 权限树 + id/fullPath -->
    <WebResourceProvider class="..."/>       <!-- 加载 bundle.js -->
    <ControllerRegisterProvider class="..."/> <!-- Spring REST -->
</extra-decision>
```

## 2. 架构分层（推荐）

```
plugin.xml
├── locale/          LocaleFinder + *.properties（\u 转义中文）
├── decision/        管理系统 UI + REST 配置 API
├── web/             预览页 JS/CSS + WebService + Action
└── core/            业务逻辑、配置存储、权限、与引擎交互
```

原则：

- **core** 不依赖 Spring、不依赖 BI；可被 web 与 decision 共用。
- **decision** 的 REST 只做参数校验与调用 core；权限用 `@VisitRefer`，不要用「预览白名单」拦管理接口。
- **web** 预览接口用 `ActionNoSessionCMD` + `NoSessionIDService`，在 Action 内自己做 session/用户校验。

## 3. 什么时候调用哪个接口

### 3.1 决策平台（管理系统）

| 场景 | 调用方式 | 说明 |
|------|----------|------|
| 读/写插件配置 | 自研 `@Controller` + `Dec.reqGet` / `Dec.reqPost` | 路径如 `/report/debug/assistant/config/get|save` |
| 管理端鉴权 | `@VisitRefer(required = true)` | 走决策登录态；**不要**用预览授权用户列表拦 GET/POST |
| 拉平台用户列表 | `Dec.Utils.reqPlatformUsers({page,count,keyword})` | 授权用户下拉；`item.value` 格式为 `显示名(用户名)` |
| 保存授权用户（推荐） | 官方 `dec.case.platform.user` + 弹层「确定」 | 提交 **显示名(用户名)**；磁盘存 `用户名\|显示名(用户名)` |
| 注册侧栏菜单 | `BI.config("dec.constant.management.navigation", …)` | `id` 必须与 `SystemOptionProvider.id()` 一致 |
| 注册配置卡片 | `BI.shortcut("dec.management.plugin.xxx", Widget)` | `cardType` 与 navigation 节点一致 |
| 加载脚本/样式 | `WebResourceProvider` → `ReportDebugOptionClient` | `ScriptPath.build("/com/fr/.../bundle.js")` |

**SystemOptionProvider 要点：**

```java
public String displayName() {
    return "Fine-Plugin_XXX";  // 必须返回 i18n 键，禁止 getLocText()
}
public String id() { return "decision-management-xxx"; }
public String parentId() { return "decision-management-root"; }
public String fullPath() { return "decision-management-root"; }
```

### 3.2 报表预览页

| 场景 | 调用方式 | 说明 |
|------|----------|------|
| 注入 JS/CSS | `AbstractJavaScriptFileHandler` / `AbstractCssFileHandler` | `pathsForFiles()` 可按配置返回空数组，避免无效注入 |
| 取当前预览 session | `FR.SessionMgr.getSessionID()` 或 URL `sessionID` | 快照 API 必带 |
| 先问能否用功能 | `GET ?op=report_debug&cmd=access&sessionID=` | 再创建悬浮球；须返回 JSON `{"success":true,"data":{"allowed":true}}` |
| 拉快照数据 | `GET ?op=report_debug&cmd=snapshot&sessionID=&refresh=0\|1` | `refresh=1` 强制重建 |
| 注册 op | `NoSessionIDService` → `actionOP()` 返回 `report_debug` | **cmd 从请求参数读**，不是 `process()` 第三参 |
| **主 API 路径** | `{prefix}/ReportServer?op=report_debug&cmd=...` | `op` **只**注册在 ReportServer；**禁止**打到 `/decision/view/report`（404） |
| **REST 备用** | `{prefix}/decision/report/debug/assistant/preview/access\|snapshot` | 生产 ReportServer 被登录拦截时用；`DebugAssistantPreviewResource` |
| **路径 prefix** | 因部署而异 | 本地常见 `/webroot`；决策根部署可能无 prefix 或 `/decision` |

**URL 探测（本插件 `report_debug_assistant.js`）：**

- `collectReportServerBases()`：尝试 `/webroot/ReportServer`、`/ReportServer`、由 `FR.servletURL` 推导等。
- `collectDecisionRestBases()`：尝试 `/webroot/decision`、`/decision` 等 + REST 路径。
- 成功后缓存 `state.apiReportServerBase` 或 `state.apiRestBase` 供 snapshot 复用。
- `FR.servletURL` 常为 `/decision/view/report`（**不含 webroot**），须结合 `location.pathname`（预览 iframe）推导 prefix。

**悬浮球 UI：** 显示 `SQL`，`title=数据集调试助手`；`#fr-report-debug-ball` 仅在 `access` 通过后创建。

**WebService 分发（易错）：**

```java
// process(request, response, frameworkOp) 第三参是 op=report_debug，不是 cmd
String cmd = WebUtils.getHTTPRequestParameter(request, "cmd");
snapshotAction.actionCMD(request, response, cmd);
```

### 3.3 报表会话与数据集（引擎）

| 场景 | API | 说明 |
|------|-----|------|
| 校验 session 有效 | `SessionPoolManager.getSessionIDInfor(sessionId, TemplateSessionIDInfo.class)` | 返回 null 即无效；**不要**只用 `hasSessionID` |
| 遍历数据集 | `session.getTableDataSource()` + `getTableDataNameIterator()` | |
| 数据集是否已执行 | `session.getCachedDataModel(name)` 或 `getTableDataSizeMap()` | |
| 取 DB 数据集 SQL 模板 | `((DBTableData) td).getQuery()` | |
| 解析执行后 SQL | 缓存 `DataModel` 反射 sql 字段 → `SqlInfor` 日志 → `getNewQuery` → `ParameterHelper` | 见 `ReportDebugExecutedSqlResolver` |
| 参数展示 | `tableData.getParameters(calculator)` + `Calculator.processParameters` | 见 `ReportDebugParameterResolver` |
| SQL 执行耗时（ESD） | `ExecutedTableDataInfoManager.getInstance().getList()` | **每快照构建只扫一遍**，按数据集名索引 |

### 3.4 用户身份与权限（预览）

优先级建议（与本插件一致）：

```
1. 配置了 authorizedUsers 白名单？
   → LoginService / Cookie 解析 username，与白名单比对（normalizeUsername）
2. 否则 loginAuthOpen == true？
   → 必须解析到非空 username
3. 否则
   → 有效 report sessionID 即可
```

| 场景 | API |
|------|-----|
| 决策/平台登录用户 | `LoginService.getInstance().getCurrentUserNameFromRequest(request)` 及 Cookie 系列 |
| 预览 session 内用户 | `session.getParameterValue("fine_username")` / `getAllPara()` 等 |
| 显示名 → 登录名 | `艾可(eoco)` → `eoco`：`lastIndexOf('(')` 取括号内 |

**不要做：**

- 管理配置 API 用预览白名单鉴权 → 决策页 403。
- URL 传 `fine_username` 作唯一凭据 → 日志泄露；应依赖 Cookie + LoginService（本插件 P1 已去掉）。

### 3.5 配置持久化

| 场景 | 做法 |
|------|------|
| 插件配置目录 | **JAR 同级插件目录** `WEB-INF/plugins/plugin-{id}-{version}/` |
| 解析目录 | `ProtectionDomain.getCodeSource().getLocation()` → JAR 父目录（见 `DebugAssistantPluginPaths`） |
| 不要用 | `StableUtils.getInstallHome()` 作唯一路径（Tomcat 常指向 `bin`） |
| 键值配置 | `debug-assistant.properties` |
| 多行/含特殊字符列表 | `authorized-users.dat` UTF-8 按行存，格式 `用户名|显示名(用户名)` |

保存配置后建议：

- `configVersion++`
- 清空预览快照内存缓存（`DebugAssistantSnapshotRuntime.clearAll()`）

## 4. 前端（BI）技能点

### 4.1 授权用户组件选型

| 组件 | 何时用 | 保存方式 |
|------|--------|----------|
| `dec.case.platform.user` | **首选**，与官方调试插件一致 | 保存 **显示名(用户名)**，如 `安娜(Anna)` |
| `dec.common.order_multi_select_combo` | 需排序多选、平台用户 API 自管 | 易踩坑：`BI.map` 回调是 `(index, value)`；`getValue()` 可能返回下标 |

**平台用户数据约定：**

- 展示/提交：`显示名(用户名)`，如 `admin(admin)`、`安娜(Anna)`。
- **磁盘持久化**（`authorized-users.dat` 每行）：`用户名|显示名(用户名)`，例 `Anna|安娜(Anna)`。
- 权限白名单比对：仍取括号内**登录名**（`normalizeUsername` → `Anna`）。
- GET 给前端：
  - `authorizedUsers` → **显示名列表**（供组件 `setValue`）
  - `authorizedUsernames` → 纯登录名列表
  - `authorizedUsersText` → 磁盘原始内容（含 `|` 格式）
- **中文显示名**：不可只存 `Anna`，否则回显退化为 `Anna(Anna)`，再次保存失败。

**易错：**

- 只存登录名、GET 只返 `authorizedUsernames` → 中文用户（如 `安娜(Anna)`）无法正确回显与保存。
- `authorizedUsersFromResponse` 应优先解析 `authorizedUsersText`，再 fallback 到 `authorizedUsers`。

### 4.2 BI.map 陷阱（必记）

```javascript
// 错误：normalizeFn 只收到 index
BI.map(arr, normalizeFn);

// 正确
BI.map(arr, function (i, v) { return normalizeFn(v); });
```

### 4.3 配置页数据流

```
beforeInit → Dec.reqGet(config/get) → options.reportDebugConfig
render     → 开关/组件 selected 绑定 cfg
保存       → collectXxx() → Dec.reqPost(config/save) → 刷新 cfg / 回显
```

开关类配置：**渲染 + 保存 + 后端 GET/PUT + 真正消费逻辑** 五处必须都接线（本插件 `displayAbsolutePath` 曾只存不用）。

## 6. 国际化（Locale）

| 项 | 规则 |
|----|------|
| properties 路径 | `src/main/resources/.../locale/fr-plugin-xxx_zh_CN.properties` |
| LocaleFinder | 路径式 basename：`com/xxx/locale/fr-plugin-xxx`（与 JAR 内目录一致） |
| plugin-xml-i18n resource | `fr-plugin-xxx`（**末尾不要多一个 `-`**） |
| 中文内容 | ASCII 文件 + `\uXXXX`，避免 UTF-8 直写乱码 |
| 权限树 displayName | 返回 **键名**，不是翻译后的中文 |
| 默认无后缀 `.properties` | 通常为**英文 fallback**；生产若显示英文，查 locale 是否命中 `_zh_CN` |

## 7. 安全与性能清单（本插件已实践）

### 安全（P0）

- 默认 `loginAuthOpen=true`、`maskSqlInResponse=true`。
- 脱敏时 `querySql` 与参数 `value` 都要处理。
- 配置 API 不返回服务器路径。
- 预览鉴权不依赖 URL 用户名。

### 性能（P1/P2）

- 快照默认 `refresh=0`，手动刷新 `refresh=1`。
- 单次构建：`ExecutedSqlTimeIndex` + `SnapshotBuildContext`。
- 缓存键 `sessionId@configVersion`。
- `snapshot` 限流；`access` 不限。
- 关闭预览调试时不注入 JS。

## 8. 常见问题 → 对策

| 现象 | 原因 | 对策 |
|------|------|------|
| Can't find bundle | basename/路径不一致 | 对照 LocaleFinder 与 properties 路径（路径式 `/` 非点号） |
| 决策页/插件名英文 | locale 未加载或 fallback 到默认英文 properties | 查 `_zh_CN` 与 `basic.log` Init bundle |
| 权限树乱码 | displayName 用了中文或 UTF-8 文件 | 键名 + `\u` 转义 |
| 侧栏无菜单 | 缺 WebResource 或 navigation 未注册 | 三件套 + `BI.config` |
| 配置页 403 | 用预览白名单拦了 REST | 仅 `@VisitRefer` |
| 授权用户 `[object Object]` | value 传了对象数组 | 字符串或 `显示名(用户名)` |
| 中文用户存不住（如 `安娜(Anna)`） | 只存登录名、回显变 `Anna(Anna)` | 磁盘格式 `Anna\|安娜(Anna)`；GET 返显示名 |
| 保存 0,1 或前 N 个用户 | `BI.map`/下标当用户 | 见 4.2；优先 `dec.case.platform.user` |
| 悬浮球不显示 | access 非 JSON / 404 / 登录页 | 查 ReportServer prefix；试 REST 备用；见 3.2 |
| `__FR_REPORT_DEBUG_ASSISTANT__=true` 无球 | access 失败或 `allowed:false` | Network 看 `cmd=access` 响应 |
| access 404 | 路径 prefix 错误 | 本地试 `/webroot/ReportServer`；勿用 `/decision/view/report` |
| access 登录页 HTML | ReportServer 被决策登录拦截 | 用 REST 备用或先登录决策平台 |
| 开关无效 | 只写入 properties 未读 | 快照/预览逻辑里读 `ConfigStore` |
| 快照 403 | 白名单/登录/session | 查 `DebugPermissionHelper` 分支 |
| cmd 不生效 | cmd 从 frameworkOp 读错 | 从 `request` 参数读 `cmd` |
| 配置写 bin 目录 |用了 installHome | 用插件 JAR 旁路径 |

## 9. 新插件开发检查表（可复制）

**工程**

- [ ] `plugin.xml` id / version / `prefer-packages` / `jartime`
- [ ] `pom.xml` 与 `plugin.xml` 版本一致
- [ ] `mvn package` 通过，JAR 不含 `fine-third`

**决策页**

- [ ] SystemOption + WebResource + ControllerRegister
- [ ] `BI.config` navigation + `BI.shortcut`
- [ ] REST `@VisitRefer`，GET/POST 字段与 Store 一致
- [ ] 开关在消费端有逻辑

**预览页**

- [ ] JS Handler 可按配置关闭
- [ ] WebService op/cmd 分发正确
- [ ] access 探活 + snapshot 鉴权（JSON 非 HTML）
- [ ] ReportServer prefix 多环境验证（webroot / decision）
- [ ] 决策 REST 备用路径可通（若生产 ReportServer 被拦）
- [ ] sessionID 来源明确；悬浮球 `title` 与 i18n 一致

**数据**

- [ ] 配置目录在 `plugins/plugin-xxx/`
- [ ] 敏感字段脱敏
- [ ] 异常不向前端抛栈

**发版**

- [ ] 替换 JAR + plugin.xml，重启
- [ ] 插件禁用/启用一次（菜单/权限缓存）
- [ ] `basic.log` 无 bundle 报错

## 11. 新插件最小路径（推荐顺序）

1. 复制 `plugin.xml` + `pom.xml` 骨架，改 id/包名。  
2. 做 `LocaleFinder` + 中英文 properties（`\u`）。  
3. 做决策三件套：空白配置页能保存/读取。  
4. 再做预览 WebService + 简单 Action（ping）。  
5. 接引擎 API（Session、业务对象）。  
6. 最后做权限、脱敏、缓存、限流。
