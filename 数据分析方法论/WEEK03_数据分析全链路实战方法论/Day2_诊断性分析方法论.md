# Day2 · 诊断性分析方法论

> 诊断性分析回答"为什么发生"。从现象到根因的系统方法。

---

## 一、方法论框架

### 1. 根因分析框架

| 框架 | 适用 | 方法 |
|------|------|------|
| 5 Why | 简单问题 | 连续问 5 个为什么 |
| 鱼骨图 | 多因素问题 | 人/机/料/法/环 |
| 故障树 | 复杂系统 | 自顶向下分解 |
| 假设树 | 业务问题 | 提假设 → 验证 |

### 2. 5 Why 示例

```
现象：某产品转化率下降
Why1：因为支付页跳出率高
Why2：因为支付页加载慢（3 秒）
Why3：因为新增了风控接口
Why4：因为风控接口同步调用
Why5：因为设计时没考虑异步

根因：风控接口应异步化
```

**注意**：5 Why 不是必须 5 个，是问到"可行动的根因"为止。

### 3. 鱼骨图（因果图）

```
        人：客服响应慢
        机：服务器性能
   �────┼──── 料：库存缺货
   转化率下降
   ─────┼──── 法：流程复杂
        环：竞品促销
        测：埋点错误
```

**分类**：人/机/料/法/环/测，按业务调整。

### 4. 下钻分析

**维度下钻**：
```
转化率下降
├── 按渠道：A 渠道降、B 渠道正常
│   └── A 渠道按设备：移动端降、PC 正常
│       └── 移动端按页面：支付页降
│           └── 支付页按步骤：加载步骤慢
```

**指标下钻**：
```
转化率 = 加购率 × 结算率 × 支付率
├── 加购率：正常
├── 结算率：降
└── 支付率：正常
→ 问题在结算环节
```

**下钻边界**：下到"可定位责任主体"为止，不要下到无意义细节。

### 5. 假设验证

**流程**：
1. 提假设：可能是 X 导致
2. 设计验证：看 X 与现象是否相关
3. 判定：证伪或证实
4. 若证伪，提下一个假设

**示例**：
- 假设1：支付页改版导致 → 看改版前后转化 → 证实
- 假设2：竞品促销导致 → 看竞品价格 → 排除
- 假设3：库存缺货导致 → 看缺货率 → 证实

### 6. 诊断的陷阱

| 陷阱 | 说明 | 防范 |
|------|------|------|
| 相关当因果 | A 和 B 相关就下结论 | 找混淆变量 |
| 幸存者偏差 | 只看成功样本 | 看全量 |
| 多重比较 | 测 100 个假设总有显著 | Bonferroni 校正 |
| 锚定效应 | 先想到的原因当根因 | 系统列所有可能 |
| 停止太早 | 找到一个原因就停 | 验证是否唯一根因 |

## 二、案例复盘：某产品转化率下降诊断

### 1. 业务背景
- 某电商产品，支付转化率从 60% 降到 45%
- 业务方："帮我们找原因"

### 2. 假设树

```
转化率下降
├── H1：支付页改版
├── H2：支付方式减少
├── H3：竞品促销分流
├── H4：库存缺货
├── H5：风控拦截增加
└── H6：性能问题
```

### 3. 验证过程

| 假设 | 验证方法 | 结果 | 判定 |
|------|---------|------|------|
| H1 改版 | 改版前后 A/B | 改版组 50% vs 旧版 58% | ✅ 部分 |
| H2 支付方式 | 各方式转化 | 全部下降 | ❌ 排除 |
| H3 竞品 | 竞品价格对比 | 无显著促销 | ❌ 排除 |
| H4 缺货 | 缺货率 | 正常 | ❌ 排除 |
| H5 风控 | 拦截率 | 拦截率 +15% | ✅ 部分 |
| H6 性能 | 加载时间 | 从 1s 到 3s | ✅ 部分 |

### 4. 多根因

**发现**：不是单一原因，是三个叠加
- 改版：贡献 -5%
- 风控：贡献 -7%
- 性能：贡献 -3%

### 5. 二次下钻

**风控拦截增加**：
- 新增风控规则上线
- 拦截的订单中 70% 是误拦截
- → 风控规则过严

**性能下降**：
- 新增风控接口同步调用
- 支付页加载从 1s 到 3s
- → 应异步化

**改版**：
- 新版按钮位置变化
- A/B 测试新版差 8%
- → 回滚按钮位置

### 6. 结论与建议

**根因**（按影响排序）：
1. 风控规则过严，误拦截 70%
2. 风控接口同步调用，加载慢
3. 改版按钮位置不合理

**建议**：
1. 调整风控规则阈值，减少误拦截
2. 风控接口异步化
3. 回滚按钮位置

### 7. 教训
- 转化率下降不是单一原因
- 要系统列假设，不能锚定第一个想到的
- 多根因要按影响排序，优先解决大问题
- 相关验证后要二次下钻找可行动点

## 三、思考练习

1. 选一个你业务的异常现象，用假设树列 5 个假设并验证。
2. 用 5 Why 分析一个简单问题，找到可行动根因。
3. 回忆一次"相关当因果"的误判，找出混淆变量。
