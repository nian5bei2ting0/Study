# Day7 · 综合复盘与端到端案例

> 四类分析不是孤立的，是递进的。一个业务从描述到规范的演进是分析的成熟路径。

---

## 一、方法论框架

### 1. 四类分析的协同

```
描述（发生了什么）
  ↓ 提供现状
诊断（为什么发生）
  ↓ 找到根因
预测（会发生什么）
  ↓ 预判未来
规范（该怎么做）
  ↓ 给出最优行动
```

**关键认知**：
- 跳过描述直接预测，会脱离业务
- 跳过诊断直接规范，会治标不治本
- 四类分析要按顺序，不能跳

### 2. 何时该停止分析、开始行动

| 信号 | 含义 |
|------|------|
| 根因已定位 | 诊断到位 |
| 预测置信度够 | 预测可用 |
| 行动方案明确 | 规范完成 |
| 边际收益递减 | 再分析价值不大 |

**反模式**：分析瘫痪（Analysis Paralysis）——一直分析不行动。

### 3. 全链路图

```
业务问题
  ↓
[描述] 现状盘点 + 对比 + 结构
  ↓
[诊断] 假设树 + 下钻 + 根因
  ↓
[预测] 目标定义 + 特征 + 模型 + 不确定性
  ↓
[规范] 优化建模 + 求解 + 敏感性
  ↓
[决策] 行动方案 + 风险 + ROI
  ↓
[执行] 落地 + 监控 + 迭代
```

### 4. 分析的边界

| 边界 | 说明 |
|------|------|
| 数据边界 | 数据能不能支撑这个问题 |
| 时间边界 | 分析到什么时候必须出结论 |
| 置信边界 | 结论的置信度多少 |
| 行动边界 | 建议能被执行到什么程度 |

**好分析师知道什么时候说"数据不足以回答"**。

### 5. 分析报告的完整结构

```
1. 一句话结论
2. 背景与问题
3. 分析方法（用了哪类分析、为什么）
4. 核心发现
5. 详细分析
6. 行动建议（含优先级、预期效果）
7. 风险与边界
8. 附录
```

## 二、案例复盘：某业务从描述到规范的演进

### 1. 业务背景
- 某 SaaS 产品，年营收 1 亿
- 3 年间分析团队从 1 人到 5 人
- 分析能力从"月报"到"智能决策"

### 2. 阶段一：描述期（第 1 年）

**能力**：月度经营报表
**产出**：营收、客户数、续约率等现状指标
**问题**：业务方问"为什么续约率降了"，答不出

### 3. 阶段二：诊断期（第 1.5 年）

**能力**：根因分析
**事件**：续约率从 85% 降到 78%
**分析**：
- 假设树：续约率 = 新客户续约 + 老客户续约
- 发现：老客户续约正常，新客户续约从 70% 降到 55%
- 二次下钻：新客户中"小企业"续约率最低
- 根因：小企业版功能不足，客户用 3 个月就流失
**行动**：增加小企业版功能
**效果**：续约率回升到 82%

### 4. 阶段三：预测期（第 2 年）

**能力**：流失预警模型
**事件**：客户成功团队希望提前预警
**分析**：
- 预测目标：未来 30 天流失概率
- 特征：登录频率、功能使用、工单
- 模型：GBDT，召回 70%
- 不确定性：概率 + 置信区间
**落地**：CRM 集成，每日预警列表
**效果**：挽回率 +15%

### 5. 阶段四：规范期（第 3 年）

**能力**：客户成功资源优化
**事件**：客户成功团队人力有限，如何分配？
**分析**：
- 优化目标：最大化挽回价值
- 决策变量：每个客户成功经理分配哪些客户
- 约束：每人最多 50 客户、按地区分配
- 求解：整数规划
- 敏感性：人力 +1 能多挽回多少
**落地**：每月自动生成客户分配建议
**效果**：同等人力挽回率 +20%

### 6. 演进总结

| 阶段 | 能力 | 价值 |
|------|------|------|
| 描述 | 看见现状 | 基础 |
| 诊断 | 找到根因 | 解决已知问题 |
| 预测 | 预判未来 | 主动行动 |
| 规范 | 最优决策 | 资源最优配置 |

### 7. 关键转折点

每个阶段升级不是技术升级，是**业务方开始用分析结果做决策**：
- 描述期：业务方看月报
- 诊断期：业务方采纳根因分析改产品
- 预测期：业务方按预警名单行动
- 规范期：业务方按优化方案分配资源
