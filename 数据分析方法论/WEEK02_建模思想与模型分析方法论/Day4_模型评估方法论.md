# Day4 · 模型评估方法论

> 离线好不等于上线好。评估体系设计错了，模型上线就是灾难。

---

## 一、方法论框架

### 1. 离线评估 vs 在线评估

| 维度 | 离线评估 | 在线评估 |
|------|---------|---------|
| 数据 | 历史数据 | 实时流量 |
| 环境 | 实验室 | 生产 |
| 指标 | 模型指标（AUC/F1） | 业务指标（转化/收入） |
| 风险 | 低 | 高（影响真实用户） |
| 成本 | 低 | 高 |
| 可信度 | 中 | 高 |

**关键认知**：离线评估是必要条件，不是充分条件。离线好不等于上线好。

### 2. 为什么离线好≠上线好

| 原因 | 说明 |
|------|------|
| 分布偏移 | 上线后用户行为变了 |
| 反馈循环 | 模型改变用户行为，行为又影响模型 |
| 数据泄漏 | 离线不小心用了未来信息 |
| 评估指标错 | 优化 AUC 但业务关心收入 |
| 选择偏差 | 训练数据不代表线上流量 |
| 工程差异 | 离线特征 vs 在线特征不一致 |

### 3. 业务目标函数化

**原则**：评估指标要和业务目标对齐。

| 业务目标 | 错误指标 | 正确指标 |
|---------|---------|---------|
| 减少欺诈损失 | 准确率 | 召回率 × 单笔损失 |
| 提升推荐点击 | AUC | CTR × 停留时长 |
| 流失预警 | F1 | 召回率 × 挽回价值 |
| 库存预测 | MSE | 缺货成本 + 滞销成本 |

**成本敏感评估**：
- 欺诈漏判成本 = 欺诈金额
- 误判成本 = 客户体验损失
- 两者权衡找最优阈值

### 4. 分类评估指标

| 指标 | 适用 | 注意 |
|------|------|------|
| 准确率 | 均衡类别 | 不平衡时失效 |
| 精确率 | 误报代价高 | 如垃圾邮件 |
| 召回率 | 漏报代价高 | 如欺诈检测 |
| F1 | 平衡两者 | 精确召回同等重要 |
| AUC | 排序能力 | 不关心阈值 |
| PR-AUC | 不平衡 | 比 ROC 更敏感 |

**多分类**：average 参数
- macro：各类等权（关注小类）
- weighted：按样本量加权
- micro：全局计算（关注大类）

### 5. 回归评估指标

| 指标 | 含义 | 注意 |
|------|------|------|
| MAE | 平均绝对误差 | 抗异常 |
| MSE | 均方误差 | 对异常敏感 |
| RMSE | 均方根误差 | 量纲一致 |
| R² | 解释方差比例 | 跨模型可比 |
| MAPE | 百分比误差 | 真值为 0 时失效 |

### 6. 评估的陷阱

| 陷阱 | 说明 | 防范 |
|------|------|------|
| 数据泄漏 | 用了未来信息 | 严格时序 split |
| 时间穿越 | 验证集在训练集前 | 时序 split |
| 选择偏差 | 评估数据不代表线上 | 用最新数据评估 |
| 多重比较 | 调参时多次评估 | 用独立测试集 |
| 过拟合验证集 | 调参调到验证集 | 留出最终测试集 |

### 7. 上线前的"三道门"

```
门1：离线评估
  └── 模型指标达标 + 业务指标对齐
门2：影子测试
  └── 模型预测但不生效，对比线上模型
门3：灰度放量
  └── 小流量真实生效，监控业务指标
```

**任一道门不通过，不上线。**

## 二、案例复盘：某推荐系统评估体系

### 1. 业务背景
- 内容推荐系统，离线 AUC 0.82
- 上线后点击率反而下降 5%
- 业务方质疑模型效果

### 2. 离线评估回顾

| 指标 | 离线值 | 判定 |
|------|--------|------|
| AUC | 0.82 | 看似不错 |
| 精确率@10 | 0.35 | 一般 |
| 召回率@10 | 0.28 | 一般 |
| 业务指标 | 未评估 | ❌ |

**问题**：只看 AUC，没评估业务指标（CTR、停留时长）

### 3. 上线后根因分析

**原因 1：分布偏移**
- 离线用历史日志训练，但历史日志是旧模型推荐的
- 新模型推荐的内容，用户没见过，行为不同
- → 离线评估的数据分布 ≠ 上线分布

**原因 2：反馈循环**
- 新模型推荐新内容 → 用户点击行为变 → 影响后续推荐
- 离线评估无法模拟这个循环

**原因 3：指标错位**
- 离线优化 AUC（排序能力）
- 业务关心 CTR（点击率）+ 停留时长
- AUC 高不代表 CTR 高

### 4. 修正方案

**离线评估增强**：
- 加入 CTR 模拟评估
- 用留出的最近数据评估（更接近线上）
- 加入多样性、新颖性指标

**影子测试**：
- 新模型预测但不展示
- 对比新旧模型的推荐分布差异

**灰度放量**：
- 5% → 20% → 50% → 100%
- 每阶段监控 CTR、停留时长、负反馈

### 5. 教训
- 只看离线 AUC 就上线，等于没评估
- 推荐系统有反馈循环，离线无法完全模拟
- 评估指标必须和业务目标对齐
- 三道门缺一不可

## 三、思考练习

1. 选你的一个模型，检查评估指标是否和业务目标对齐。
2. 列出你的模型上线可能遇到的 3 种"离线好上线差"的原因。
3. 设计你模型的"三道门"评估方案。

---

## 四、今日小结

- 离线好≠上线好，分布偏移、反馈循环、指标错位是主因
- 评估指标要和业务目标对齐
- 成本敏感评估：误报和漏报代价不同
- 评估陷阱：泄漏、穿越、选择偏差
- 上线前三道门：离线 → 影子 → 灰度
