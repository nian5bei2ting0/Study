## 一、方法论框架

### 1. 选型维度

| 维度 | 关键问题 |
|------|---------|
| 问题类型 | 分类 / 回归 / 聚类 / 时序 / 排序 |
| 数据量 | 1k / 10k / 100k / 1M+ |
| 特征类型 | 表格 / 图像 / 文本 / 序列 / 图 |
| 可解释性 | 需要解释 / 黑盒可接受 |
| 实时性 | 离线批量 / 在线毫秒 |
| 工程成本 | 部署 / 维护 / 监控难度 |
| 数据平衡 | 类别是否均衡 |
| 特征数 | 低维 / 高维 |

### 2. 算法选型决策树

```
问题类型？
├── 分类
│   ├── 数据量小 + 可解释 → 逻辑回归 / 决策树
│   ├── 表格数据 + 中等量 → 随机森林 / GBDT
│   ├── 高维稀疏（文本）→ 朴素贝叶斯 / SVM
│   ├── 图像 → CNN
│   └── 极致精度 + 数据足 → 集成 / 深度学习
├── 回归
│   ├── 线性关系 + 可解释 → 线性回归 / 岭 / Lasso
│   ├── 非线性 + 表格 → 树模型
│   └── 时序 → ARIMA / Prophet / LSTM
├── 聚类
│   ├── 球形群体 → KMeans
│   ├── 任意形状 → DBSCAN
│   └── 层次结构 → 层次聚类
└── 异常检测
    ├── 单变量 → 3σ / IQR
    └── 多变量 → 孤立森林 / LOF
```

### 3. 线性 vs 树 vs 深度学习

| 维度 | 线性模型 | 树模型 | 深度学习 |
|------|---------|--------|---------|
| 可解释性 | 高 | 中 | 低 |
| 数据需求 | 小 | 中 | 大 |
| 特征工程 | 重要 | 较少 | 自动 |
| 表格数据 | 好 | 极好 | 一般 |
| 图像/文本 | 差 | 差 | 极好 |
| 训练成本 | 低 | 中 | 高 |
| 部署成本 | 低 | 中 | 高 |

**经验法则**：
- 表格数据首选树模型（GBDT/LightGBM）
- 图像/文本首选深度学习
- 需要解释首选线性/树
- 数据少首选简单模型

### 4. 集成学习"何时用"

| 方法 | 适用 | 不适用 |
|------|------|--------|
| Bagging（随机森林） | 方差大、过拟合 | 偏差大 |
| Boosting（GBDT） | 偏差大、欠拟合 | 数据噪声大 |
| Stacking | 单模型都不够好 | 工程成本敏感 |

**何时不用集成**：
- 单模型已达标
- 工程成本敏感
- 需要强可解释性

### 5. 何时不用模型

| 场景 | 替代 |
|------|------|
| 规则 < 10 条能解决 | if-else |
| 数据 < 1000 条 | 统计 + 经验 |
| 问题一次性 | 手工分析 |
| 业务不接受黑盒 | 规则或可解释模型 |
| 成本 > 收益 | 不做 |

## 二、案例复盘：某零售销量预测选型

### 1. 业务需求
- 门店级 + 周粒度 + 提前 4 周 + 可解释
- 200 家门店，单店 2 年数据（104 周数据点）
- 需要加促销、节假日、天气等特征

### 2. 候选算法

| 算法 | 优点 | 缺点 | 评估 |
|------|------|------|------|
| ARIMA | 经典时序 | 单变量，无法加特征 | ❌ |
| Prophet | 可加特征、节假日 | 解释性弱、单序列 | 备选 |
| LightGBM | 多特征、可解释（SHAP） | 需构造时序特征 | ✅ |
| LSTM | 时序强 | 数据量不足（104 点） | ❌ |

### 3. 决策过程

**ARIMA 淘汰**：
- 业务需要加促销特征，ARIMA 是单变量
- 强行用 ARIMAX 加特征，但解释性差

**LSTM 淘汰**：
- 单店 104 个数据点，远不够 LSTM
- 即使合并所有店，每个店时序模式不同

**Prophet 备选**：
- 可加节假日、促销
- 但每个店要单独训练，200 个模型维护成本高
- 解释性不如树模型

**LightGBM 选用**：
- 所有店合并训练，店 ID 作为特征
- 可加任意特征（促销、天气、节假日）
- SHAP 可解释每个预测
- 数据量足够（200 × 104 = 20800 样本）

### 4. 实施细节
- 构造时序特征：滞后值（lag_1, lag_4, lag_52）、滑动均值、环比
- 防泄漏：特征只用预测时点之前的数据
- 验证：时间序列 split，最后 8 周作测试

### 5. 教训
- 盲目上深度学习（LSTM），数据量不足效果差
- 时序问题不一定要用时序模型，树模型 + 时序特征常更优
- 可解释性需求排除了部分黑盒选项
- 数据量是硬约束，不能强行上复杂模型

## 四、今日小结

- 选型维度：问题类型、数据量、可解释性、实时性、工程成本
- 表格数据首选树模型，图像/文本首选深度学习
- 集成学习有明确适用场景
- 何时不用模型比何时用模型更重要
- 选型清单让决策可追溯
