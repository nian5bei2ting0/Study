# Day2 · 特征工程方法论

> 数据决定上限，模型只是逼近这个上限。特征工程就是"把上限拉高"。

---

## 一、方法论框架

### 1. 特征构造三原则

| 原则 | 含义 | 违反后果 |
|------|------|---------|
| 业务可解释 | 能用业务语言讲清为什么这个特征有用 | 模型不可信、难维护 |
| 时序无泄漏 | 特征不能包含预测时点之后的信息 | 离线虚高、上线崩盘 |
| 覆盖率充足 | 特征在样本中有足够非空值 | 模型对部分群体失效 |

### 2. 特征类型

| 类型 | 例子 | 构造方法 |
|------|------|---------|
| 原始 | 交易金额、用户年龄 | 直接取 |
| 衍生 | 金额分桶、年龄分段 | 转换 |
| 交叉 | 渠道×品类、地区×时段 | 组合 |
| 时序 | 近 7 日均值、环比增长率 | 窗口聚合 |
| 聚合 | 用户历史交易次数、平均金额 | 分组聚合 |

### 3. 特征选择方法分层

| 层级 | 方法 | 适用 | 成本 |
|------|------|------|------|
| 过滤法 | 方差阈值、相关系数、卡方 | 快速初筛 | 低 |
| 包装法 | 递归特征消除（RFE） | 精选 | 高 |
| 嵌入法 | 树重要性、L1 正则 | 平衡 | 中 |

**实践流程**：
1. 过滤法去掉明显无用的（方差=0、相关<0.01）
2. 嵌入法看重要性排序
3. 业务知识二次筛选
4. 包装法精修（可选）

### 4. 特征稳定性：PSI

**PSI（Population Stability Index）**：衡量特征分布随时间的变化。

| PSI 值 | 判定 | 行动 |
|-------|------|------|
| < 0.1 | 稳定 | 无需行动 |
| 0.1 - 0.25 | 轻微漂移 | 监控 |
| > 0.25 | 显著漂移 | 重新训练 |

**公式**：PSI = Σ (实际占比 - 预期占比) × ln(实际占比 / 预期占比)

### 5. 特征衰减

**误区**：时间越近的特征权重越高？不一定。
- 长周期模式：历史 90 天比近 7 天更稳
- 突发事件：近 1 天比近 30 天更敏感
- **关键**：根据业务节奏选择时间窗口，不是越近越好

### 6. 领域知识 > 自动特征生成

| 方式 | 优点 | 缺点 |
|------|------|------|
| 人工特征 | 可解释、稳定 | 依赖经验、耗时 |
| 自动特征（Featuretools） | 快、覆盖广 | 不可解释、可能泄漏 |

**实践**：人工为主，自动为辅。自动生成的特征必须过业务解释关。

### 7. 特征工程清单

每个特征要回答：
- [ ] 业务含义是什么？
- [ ] 数据来源可靠吗？
- [ ] 覆盖率多少？
- [ ] 有无时序泄漏？
- [ ] 分布稳定吗（PSI）？
- [ ] 与目标的相关性？
- [ ] 与其他特征共线性？

## 二、案例复盘：某信贷反欺诈特征体系

### 1. 业务背景
- 反欺诈模型，识别信用卡套现交易
- 原始字段：20 个（交易表 + 账户表）
- 目标：构造有效特征体系

### 2. 特征构造过程

**原始字段**：交易金额、时间、渠道、商户、账户 ID、开户时间、信用额度...

**衍生特征（80+）**：

| 类别 | 特征 | 业务含义 |
|------|------|---------|
| 金额 | 单笔金额 / 信用额度占比 | 套现常接近额度上限 |
| 金额 | 金额分散度（标准差/均值） | 套现金额常分散多笔 |
| 频率 | 近 1 小时交易次数 | 异常高频 |
| 频率 | 频率突变（近 1h / 历史 7d 均值） | 行为突变 |
| 时间 | 深夜交易占比 | 套现常在深夜 |
| 时间 | 交易间隔标准差 | 套现间隔规律 |
| 商户 | 同商户集中度 | 套现常固定商户 |
| 商户 | 商户风险等级（外部） | 高风险商户 |
| 设备 | 设备-账户不一致 | 异常 |
| 设备 | 新设备占比 | 风险 |
| 行为 | 金额接近整数占比 | 套现常整数金额 |
| 行为 | 交易后立即还款占比 | 套现特征 |

### 3. 特征选择

**第一轮（过滤法）**：
- 删除方差 < 0.01 的特征（5 个）
- 删除与目标相关 < 0.02 的特征（10 个）

**第二轮（嵌入法）**：
- 用 LightGBM 训练，看特征重要性
- 保留 Top 30

**第三轮（业务筛选）**：
- "设备-账户不一致"重要性第 3，但业务确认是强信号 → 保留
- "交易后立即还款"重要性第 25，但业务确认是套现核心 → 保留
- 某自动交叉特征重要性高但无法解释 → 删除

### 4. PSI 监控

| 特征 | 上线时 | 3 个月后 | PSI | 行动 |
|------|--------|---------|-----|------|
| 深夜交易占比 | 稳定 | 略升 | 0.08 | 监控 |
| 金额分散度 | 稳定 | 显著变化 | 0.31 | 重训 |
| 新设备占比 | 稳定 | 稳定 | 0.05 | 无 |

### 5. 教训
- 纯靠算法选特征，漏掉"设备-账户不一致"（重要性低但业务强）
- 自动交叉特征重要性高但不可解释，上线后出问题难排查
- PSI 监控发现"金额分散度"漂移，及时重训避免模型衰退

## 三、思考练习

1. 选你最近建的模型，列出 3 个最依赖业务知识的特征。
2. 检查这些特征有无时序泄漏风险。
3. 设计一个 PSI 监控方案：监控哪些特征、多久算一次、阈值多少。

---

## 四、今日小结

- 特征构造三原则：业务可解释、时序无泄漏、覆盖率充足
- 特征选择分层：过滤 → 嵌入 → 业务
- PSI 监控特征漂移
- 领域知识 > 自动生成
- 每个特征都要过"业务解释关"
