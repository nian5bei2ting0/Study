# Day7 · 综合复盘与模型交接文档

> 模型不是终点，能用起来、能维护、能传承才是终点。

---

## 一、方法论框架

### 1. 模型全生命周期

```
需求 → 数据 → 特征 → 建模 → 评估 → 上线 → 监控 → 重训 → 退役
```

**关键认知**：建模只占 20%，上线后维护占 80%。交接文档是维护的基础。

### 2. 上线前的"三道门"

**门 1：离线评估**
- 模型指标达标（AUC/F1/RMSE）
- 业务指标对齐（成本/收益）
- 公平性审计通过
- 通过标准：所有指标达标

**门 2：影子测试**
- 模型预测但不生效
- 对比线上模型的预测分布
- 监控预测延迟、稳定性
- 通过标准：分布合理、性能达标

**门 3：灰度放量**
- 5% → 20% → 50% → 100%
- 每阶段监控业务指标
- 护栏指标恶化则回滚
- 通过标准：业务指标正向、护栏稳定

### 3. 效果监控体系

| 监控类型 | 监控内容 | 频率 | 告警 |
|---------|---------|------|------|
| 性能监控 | AUC/F1/RMSE | 日 | 降幅 > 5% |
| 数据漂移 | 特征分布 PSI | 周 | PSI > 0.25 |
| 业务监控 | 业务指标 | 日 | 降幅 > 阈值 |
| 系统监控 | 延迟/可用性 | 实时 | 延迟 > P99 |

### 4. 模型衰退应对

| 策略 | 适用 | 触发 |
|------|------|------|
| 触发式重训 | 数据漂移显著 | PSI > 0.25 |
| 定时重训 | 周期性变化 | 每月/季 |
| 主动学习 | 标注成本高 | 不确定样本优先标注 |
| 模型回滚 | 性能骤降 | AUC 降 > 10% |

### 5. 价值复盘

**ROI 计算**：
```
ROI = (模型带来的收益 - 建模成本 - 部署成本 - 维护成本) / 总成本
```

**收益**：
- 增收：转化提升 × 客单价
- 降本：人力节省、损失减少
- 效率：处理速度提升

**成本**：
- 建模：人力 × 时间
- 部署：工程 + 算力
- 维护：监控 + 重训 + 人力

### 6. 模型退役标准

- 性能持续低于基线
- 业务场景消失
- 被新模型替代
- 维护成本 > 收益

### 7. 模型交接文档要素

```
1. 业务背景：解决什么问题
2. 数据说明：数据源、时间、字段
3. 特征清单：特征定义、来源、重要性
4. 模型说明：算法、参数、版本
5. 评估结果：离线 + 在线指标
6. 部署信息：服务地址、接口、依赖
7. 监控方案：监控项、告警阈值
8. 回滚方案：如何回退
9. 联系人：负责人、备份人
10. 变更记录：版本历史
```

## 二、案例复盘：某 SaaS 流失预警全链路

### 1. 业务背景
- 客户成功团队希望提前 30 天预警高流失风险客户
- 目标：召回率优先（宁可误报不漏报）

### 2. 全链路

**问题定义**：
- 流失定义：连续 60 天无登录
- 预警目标：未来 30 天流失概率
- 行动：客户成功团队针对性介入

**指标体系**：
- 北极星：客户续约率
- 模型指标：召回率（目标 > 70%）、精确率（目标 > 30%）

**数据**：
- 客户行为：登录频率、功能使用深度、工单数
- 客户属性：行业、规模、合同剩余期
- 时间窗口：近 90 天行为

**特征工程**：
- 登录频率突变（近 7d / 历史 30d 均值）
- 核心功能使用下降率
- 工单未解决数
- 合同剩余天数

**建模**：
- 算法：GBDT（可解释 + 表格数据 + 中等数据量）
- 评估：时间序列 split，最后 2 个月作测试

**评估**：
| 指标 | 离线 | 影子 | 灰度 |
|------|------|------|------|
| 召回率 | 75% | 73% | 71% |
| 精确率 | 35% | 33% | 32% |

**落地**：
- 集成到 CRM，客户成功团队每日看预警列表
- 高风险客户：48 小时内主动联系

**监控**：
- 月度 PSI 监控特征漂移
- 月度召回率监控
- 季度重训

**价值**：
- 挽回率提升 15%
- ROI = 4.2（收益 200 万 / 成本 47 万）

### 3. 失败点复盘

**第一版失败**：
- 只看准确率，召回率 40%
- 业务方："漏了 60% 的高风险客户，没用"
- → 重新调阈值，召回优先

**教训**：
- 评估指标要和业务目标对齐
- 流失场景召回 > 精确
- 模型不是终点，业务用起来才是

### 4. 交接文档（精简版）

```
模型名：客户流失预警 v1.2
负责人：张三 / 备份：李四
业务背景：提前 30 天预警流失客户
数据：客户行为表（近 90 天）
特征：8 个（登录突变、功能使用下降、工单、合同期）
模型：LightGBM，参数见 config.yaml
评估：召回 71%，精确 32%
部署：流失预测服务 /predict
监控：月度 PSI + 召回率
回滚：保留 v1.1，可一键切换
变更：v1.0 → v1.1（加特征）→ v1.2（调阈值）
```
