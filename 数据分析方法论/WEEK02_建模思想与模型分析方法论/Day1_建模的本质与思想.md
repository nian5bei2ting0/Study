# Day1 · 建模的本质与思想

> 在动手建模型前，先想清楚：模型到底是什么？为什么需要它？

---

## 一、方法论框架

### 1. 模型是什么

**定义**：模型 = 对现实的简化抽象 + 一组显式假设。

**三个要素**：
- **简化**：忽略次要因素，保留主要因素
- **抽象**：把业务问题映射成数学结构
- **假设**：明确"在什么条件下模型有效"

**例**：
- 线性回归假设：变量间是线性关系、误差独立同分布、无多重共线性
- 逻辑回归假设：对数几率是线性的
- 决策树假设：特征空间可递归切分

**关键认知**：所有模型都是错的，但有些是有用的（George Box）。模型的有效性 = 假设成立程度 × 数据代表性。

### 2. 建模三问

动手前必问：

| 问题 | 不通过的表现 |
|------|-------------|
| 有没有更简单的解？ | 规则能解决却上模型 |
| 数据是否足够？ | 样本量 < 特征数 × 10 |
| 业务能否接受？ | 黑盒模型用于合规场景 |

**简单解优先级**：
1. 业务规则（if-else）
2. 统计方法（均值、分位数）
3. 简单模型（线性、树）
4. 复杂模型（集成、深度学习）

### 3. 偏差-方差权衡

| 误差来源 | 含义 | 表现 | 对策 |
|---------|------|------|------|
| 偏差（Bias） | 模型太简单，欠拟合 | 训练误差高 | 加复杂度 |
| 方差（Variance） | 模型太复杂，过拟合 | 训练低测试高 | 减复杂度/正则 |
| 不可约误差 | 数据噪声 | 无法消除 | 接受 |

**直觉**：
- 欠拟合：模型学不到规律（用线性拟合非线性数据）
- 过拟合：模型学到噪声（把训练集的偶然模式当规律）
- 甜点：偏差和方差都适中

**诊断**：
- 训练误差高 + 测试误差高 → 欠拟合
- 训练误差低 + 测试误差高 → 过拟合
- 训练误差低 + 测试误差低 → 刚好

### 4. 奥卡姆剃刀

**原则**：能用简单模型不用复杂模型。

**理由**：
- 简单模型更可解释
- 简单模型更稳定（方差小）
- 简单模型工程成本低
- 简单模型更易调试

**何时用复杂模型**：
- 简单模型精度不够（已验证）
- 数据量足够支撑复杂度
- 可解释性要求低
- 工程能力能支撑

### 5. 何时不用模型

| 场景 | 替代方案 |
|------|---------|
| 规则能解决（< 10 条规则） | if-else |
| 数据太少（< 1000 条） | 统计方法 + 业务经验 |
| 成本不划算 | 不做 |
| 业务不接受黑盒 | 用可解释模型或规则 |
| 问题是一次性的 | 手工分析 |
| 数据质量太差 | 先治理数据 |

### 6. 建模的"为什么"

每次建模前写下：
1. **业务问题**：要解决什么？（不是"建个模型"）
2. **现状基线**：现在怎么解决？效果如何？
3. **预期提升**：模型上线后能提升多少？
4. **成本估算**：建模 + 部署 + 维护成本
5. **决策门槛**：达到什么效果才值得上线？

## 二、案例复盘：某场景"该不该建模"的决策

### 1. 业务背景
- 某电商客服团队，每天 5000 条用户咨询
- 业务方："建个模型自动分类咨询，提升效率"

### 2. 建模三问

**Q1：有没有更简单的解？**
- 现状：人工分类，准确率 95%，耗时 30 秒/条
- 简单方案：关键词匹配规则
- 测试：规则能覆盖 60% 的常见问题，准确率 85%
- **结论**：规则能解决一部分，但长尾问题不行

**Q2：数据是否足够？**
- 历史咨询数据：50 万条，已人工标注
- 类别：20 类，最少类 2000 条
- **结论**：数据充足

**Q3：业务能否接受？**
- 场景：自动分类后转人工复核
- 可解释性：需知道为什么分到某类
- **结论**：可接受，因为是辅助而非替代

### 3. 成本-收益分析

| 项 | 估算 |
|----|------|
| 建模成本 | 2 人月 |
| 部署成本 | 1 人月 |
| 维护成本 | 0.5 人月/年 |
| 预期效果 | 自动分类 80%，准确率 90% |
| 节省 | 每天节省 4000 条 × 30 秒 = 33 小时人力 |

**决策**：值得建模。

### 4. 反面案例：不该建模的场景

- 某团队想建"员工离职预测模型"
- 数据：200 名员工，3 年数据，离职 30 人
- 建模三问：
  - 简单解：HR 谈话 + 满意度调查更直接
  - 数据：样本量 30，远不够
  - 业务：预测后能否行动？HR 能干预吗？
- **结论**：不建模，改用定期访谈 + 满意度追踪

### 5. 教训
- 不是所有问题都需要模型
- "建模三问"是第一道筛子
- 成本-收益要算清，包括维护成本
- 模型不是终点，业务能用起来才是

## 四、今日小结

- 模型 = 简化 + 抽象 + 假设
- 建模三问：简单解？数据够？业务接受？
- 偏差-方差权衡决定模型复杂度
- 奥卡姆剃刀：简单优先
- 不是所有问题都需要模型
