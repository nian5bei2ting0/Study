# Day6 · AI 数据产品与智能分析 Agent

> 从"分析报告"到"智能 Agent"，数据分析的产品化是下一个前沿。

---

## 一、方法论框架

### 1. AI 数据产品的类型

| 类型 | 形式 | 例子 |
|------|------|------|
| 自然语言取数 | 对话式 BI | "上月 GMV 多少" |
| 智能归因 | 自动下钻 | "为什么 GMV 降了" |
| 智能预警 | 主动告警 | "某指标异常" |
| 分析 Agent | 自主完成分析 | 端到端分析任务 |
| 决策助手 | 推荐行动 | "建议怎么做" |

### 2. 自然语言取数（NL2SQL）

**架构**：
```
用户问题
  ↓
意图理解（LLM）
  ↓
Schema 匹配
  ↓
SQL 生成（LLM）
  ↓
SQL 审核 + 执行
  ↓
结果返回 + 可视化
```

**关键挑战**：
- 口径理解："上个月"是自然月还是滚动 30 天？
- Schema 复杂：多表 join
- 业务术语：GMV 的定义

**解决**：
- 提供指标字典给 LLM
- Few-shot 示例
- 生成后人工审核（关键场景）

### 3. 智能归因

**能力**：自动下钻定位根因

**流程**：
```
指标异常告警
  ↓
自动按维度下钻（渠道/品类/地区）
  ↓
识别异常维度
  ↓
生成归因报告
```

**价值**：从"告警"到"为什么告警"自动化。

### 4. 分析 Agent 架构

**Agent = 规划 + 工具调用 + 反思**

```
用户："分析上月销售情况"
  ↓
[规划]：拆解为子任务
  1. 取上月销售数据
  2. 做描述性分析
  3. 做同比环比
  4. 做结构拆解
  5. 生成报告
  ↓
[工具调用]：调用 SQL/Python/可视化工具
  ↓
[反思]：检查结果合理性
  ↓
[输出]：分析报告
```

**核心组件**：
- Planner：任务分解
- Tools：SQL/Python/搜索/可视化
- Memory：上下文记忆
- Reflector：自我检查

### 5. 数据产品的产品化思维

| 要素 | 说明 |
|------|------|
| 用户场景 | 谁在什么场景用 |
| 核心价值 | 解决什么痛点 |
| 交互方式 | 对话/仪表盘/告警 |
| 信任机制 | 如何让用户信结果 |
| 反馈闭环 | 用户反馈如何改进 |

**关键**：不是"能用 AI"，是"用户愿意用"。

### 6. AI 数据产品的风险

| 风险 | 防范 |
|------|------|
| 结果错误 | 人工审核机制 |
| 数据安全 | 权限 + 脱敏 |
| 过度信任 | 标注"AI 生成" |
| 依赖单一模型 | 多模型备份 |
| 成本失控 | 调用频率限制 |

## 二、案例复盘：某公司智能分析 Agent 设计

### 1. 业务背景
- 某电商，管理层希望"问一句话就能得到分析"
- 现状：每次分析要提工单，3 天出结果
- 目标：实时分析问答

### 2. Agent 架构

```
用户问题
  ↓
[意图识别]：是取数/分析/预测/建议？
  ↓
[规划]：拆解子任务
  ↓
[工具调用]：
  - SQL 工具：取数
  - Python 工具：分析
  - 搜索工具：查指标定义
  - 可视化工具：画图
  ↓
[反思]：结果合理吗？
  ↓
[输出]：文字 + 图表 + 数据
```

### 3. 关键设计

**意图分类**：
| 意图 | 例子 | 处理 |
|------|------|------|
| 取数 | "上月 GMV" | NL2SQL |
| 描述 | "销售概况" | 取数 + 统计 |
| 诊断 | "为什么降了" | 下钻归因 |
| 预测 | "下月会怎样" | 调预测模型 |
| 建议 | "该怎么做" | 规范分析 |

**Schema 注入**：
- 提供表结构、字段定义、指标字典
- Few-shot 示例（常见问题 → SQL）

**审核机制**：
- 关键指标（财务）人工审核
- 非关键（运营）直接返回

**安全**：
- 按角色限制可查数据范围
- 敏感字段脱敏

### 4. 落地效果

| 指标 | 引入前 | 引入后 |
|------|--------|--------|
| 分析响应时间 | 3 天 | 3 分钟 |
| 取数工单量 | 80/月 | 20/月 |
| 管理层满意度 | 60% | 85% |
| 错误率 | - | 5%（有审核） |

### 5. 失败点

- 第一版没有 schema 注入，SQL 错误率 30%
- 加 schema + few-shot 后降到 5%
- 关键指标没审核机制，出过口径错误
- 加审核后解决

### 6. 教训
- Agent 不是"接个 LLM"，要设计架构
- Schema 和指标字典是关键
- 关键场景必须人工审核
- 产品化要考虑用户信任和反馈
