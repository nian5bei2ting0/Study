# Day3 · Prompt 工程在数据分析中的应用

> 好的 Prompt 让 AI 从"随机助手"变"专业分析师"。

---

## 一、方法论框架

### 1. Prompt 工程核心原则

| 原则 | 说明 |
|------|------|
| 角色设定 | 让 AI 扮演专业角色 |
| 上下文充分 | 给足背景信息 |
| 任务明确 | 清晰说明要做什么 |
| 输出格式 | 指定输出结构 |
| 示例引导 | Few-shot 提供范例 |
| 分步推理 | CoT 让 AI 一步步想 |

### 2. 分析专用 Prompt 模板结构

```
[角色]：你是一位资深数据分析师，擅长 [具体领域]。
[背景]：业务场景是 [描述]，数据是 [描述]。
[任务]：请完成 [具体任务]。
[要求]：
  1. [要求1]
  2. [要求2]
[输出格式]：[指定格式]
[示例]：（可选）参考以下范例...
```

### 3. 结构化输出

**为什么**：让 AI 输出可解析、可复用。

**方法**：
- JSON 格式
- Markdown 表格
- 代码块
- 固定模板

**示例**：
```
请以 JSON 格式输出，包含以下字段：
{
  "hypotheses": [
    {"id": 1, "hypothesis": "...", "validation_method": "..."},
    ...
  ]
}
```

### 4. 链式推理（CoT）

**适用**：复杂分析任务

**Zero-shot CoT**：
```
请一步步分析，最后给出结论。
```

**Few-shot CoT**：
```
示例1：
问题：...
思考：第一步...第二步...结论...
示例2：
问题：...
思考：第一步...第二步...结论...

现在请分析：
问题：...
```

**适用**：根因分析、假设验证、模型选择推理
**不适用**：简单取数、直接计算

### 5. 自我验证

**让 AI 检查自己的输出**：
```
请检查你刚才生成的 SQL：
1. 表名和字段名是否正确？
2. 口径是否符合"上个月"的定义？
3. 是否有数据泄漏风险？
如有问题，请修正。
```

**价值**：减少幻觉和口径错误。

### 6. 分析专用 Prompt 模板库

**EDA Prompt**：
```
[角色]：你是资深数据分析师。
[数据]：表名、字段、时间范围、样本量。
[任务]：生成完整 EDA 代码，包含：
  1. 数据概览
  2. 缺失值分析
  3. 单变量分布
  4. 双变量关系
  5. 异常值检测
[输出]：Python 代码 + 每步说明。
```

**报告 Prompt**：
```
[角色]：你是数据分析顾问。
[背景]：业务问题 + 分析发现。
[任务]：撰写分析报告，结构：
  1. 一句话结论
  2. 背景
  3. 核心发现（3-5 个）
  4. 详细分析
  5. 行动建议
[要求]：结论先行，每条建议含"谁、做什么、预期效果"。
```

**特征工程 Prompt**：
```
[角色]：你是特征工程专家。
[业务]：[场景描述]。
[原始字段]：[字段列表]。
[任务]：列出 10 个衍生特征，每个包含：
  1. 特征名
  2. 计算方法
  3. 业务含义
  4. 预期作用
```

**模型选择 Prompt**：
```
[角色]：你是机器学习顾问。
[问题]：[问题类型]。
[数据]：[数据量、特征类型]。
[约束]：[可解释性、实时性、工程成本]。
[任务]：推荐 3 个候选模型，对比优缺点，给出推荐和理由。
```

## 二、案例复盘：用 Prompt 生成分析报告框架

### 1. 任务
为"某产品转化率下降"生成分析报告框架。

### 2. Prompt 设计

```
[角色]：你是资深数据分析顾问，擅长电商转化分析。
[背景]：某电商产品支付转化率从 60% 降到 45%，时间：上月。
[数据]：用户行为日志、支付日志、风控日志。
[任务]：生成分析报告框架，包含：
  1. 一句话结论（待填）
  2. 背景与问题
  3. 分析方法（用哪类分析、为什么）
  4. 假设树（至少 5 个假设）
  5. 验证方案（每个假设的验证方法）
  6. 可能的根因分类
  7. 行动建议框架
[输出]：Markdown 格式，结构清晰。
[要求]：假设要 MECE，验证方法要可执行。
```

### 3. LLM 输出（精简）

```markdown
## 一句话结论
（待分析后填写）

## 背景与问题
- 问题：支付转化率 60% → 45%
- 时间：上月
- 影响：订单损失预估 X 万

## 分析方法
诊断性分析（找根因），辅以描述性（现状）

## 假设树
1. H1：支付页改版影响
   - 验证：改版前后 A/B 测试
2. H2：支付方式减少
   - 验证：各支付方式转化率对比
3. H3：风控拦截增加
   - 验证：拦截率趋势
4. H4：性能下降
   - 验证：页面加载时间趋势
5. H5：竞品促销分流
   - 验证：竞品价格对比

## 验证方案
| 假设 | 指标 | 数据源 | 判定标准 |
|...|

## 可能根因分类
- 产品层：改版、性能
- 风控层：规则调整
- 外部层：竞品

## 行动建议框架
1. 短期：回滚改版 / 调风控
2. 中期：性能优化
3. 长期：监控体系
```

### 4. 人工审核

| 项 | 评估 |
|----|------|
| 假设 MECE | ✓ 基本覆盖 |
| 验证可执行 | ✓ |
| 遗漏点 | 缺"用户群体变化"假设 → 补充 |
| 口径 | ✓ |

### 5. 效率对比

| 方式 | 时间 | 质量 |
|------|------|------|
| 人工写框架 | 1 小时 | 高 |
| LLM 生成 + 审核 | 15 分钟 | 中高（需补充） |

### 6. 教训
- Prompt 要给足背景和角色
- 输出格式要明确（Markdown/JSON）
- LLM 生成框架快，但需人工补充
- 自我验证 Prompt 能减少错误

---

## 三、思考练习

1. 为你的一个分析任务设计 Prompt，包含角色/背景/任务/输出格式。
2. 用 CoT Prompt 让 AI 分析一个根因问题。
3. 设计一个自我验证 Prompt，检查 AI 输出的 SQL。

---

## 四、今日小结

- Prompt 核心：角色 + 背景 + 任务 + 输出格式
- 结构化输出让结果可解析
- CoT 适合复杂分析，不适合简单取数
- 自我验证减少幻觉
- 建立个人 Prompt 模板库
