# Day2 · LLM 作为数据分析副驾

> LLM 不是万能的，但作为"分析副驾"能显著提效。关键是知道何时用、怎么用、怎么验。

---

## 一、方法论框架

### 1. LLM 在数据分析中的四种用法

| 用法 | 输入 | 输出 | 可信度 |
|------|------|------|--------|
| 对话式取数 | 自然语言 | SQL | 中（需审核） |
| 代码生成 | 需求描述 | Python 代码 | 高 |
| 解释辅助 | 代码/结果 | 解释文字 | 中 |
| 洞察假设 | 数据描述 | 假设清单 | 中（需验证） |

### 2. 对话式取数（NL2SQL）

**流程**：
```
用户："上个月各渠道的 GMV 是多少？"
  ↓
LLM：SELECT channel, SUM(gmv) FROM ... WHERE dt >= '...' GROUP BY channel
  ↓
执行 SQL → 返回结果
```

**风险**：
- 口径错误：LLM 对"上个月"理解偏差
- 表名/字段名错误：LLM 不知道实际 schema
- 复杂查询出错：多表 join 容易错

**防范**：
- 提供 schema 定义给 LLM
- 生成 SQL 后人工审核
- 复杂查询分步生成

### 3. 代码生成

**适用**：EDA 代码、可视化代码、数据清洗代码

**示例 Prompt**：
```
我有以下数据：
- 表名：transactions
- 字段：txn_id, account_id, amount, ts, channel
- 时间范围：2024-01-01 到 2024-12-31

请生成 Python 代码完成以下 EDA：
1. 数据概览（行数、字段类型）
2. 缺失值统计
3. amount 的分布（直方图 + 统计量）
4. 按 channel 分组的 amount 统计
5. 按月的交易量趋势
```

**优势**：LLM 生成代码比人写快 5-10 倍，且可复用。

### 4. 解释辅助

**场景**：
- 解释复杂代码逻辑
- 解释模型结果（SHAP 值含义）
- 解释统计概念

**示例**：
```
这段代码在做什么？
[粘贴代码]
```

**价值**：降低学习曲线，加速理解。

### 5. 洞察假设生成

**用法**：给 LLM 数据描述，让它提假设

**示例 Prompt**：
```
数据：某电商交易数据，上月 GMV 环比下降 10%。
字段：渠道、品类、地区、金额、时间。
请列出 5 个可能导致 GMV 下降的假设，每个假设说明验证方法。
```

**价值**：拓宽思路，避免锚定。

**注意**：LLM 提的假设仍需人工验证，不能直接当结论。

### 6. 风险管理

| 风险 | 防范 |
|------|------|
| 幻觉 | 关键结论验证数据 |
| 口径错 | SQL 人工审核 |
| 数据安全 | 敏感数据不上传 |
| 过度依赖 | 保持核心能力 |

**数据安全分级**：
- 公开数据：可上传
- 内部数据：脱敏后上传
- 敏感数据：不上传，只用本地模型

## 二、案例复盘：用 LLM 完成 EDA 全流程

### 1. 任务
对某交易数据集做完整 EDA，对比人工效率。

### 2. 数据描述（给 LLM）
```
表：transactions（50 万行）
字段：txn_id, account_id, amount, ts, channel, status
时间：2024-01-01 到 2024-06-30
```

### 3. LLM 辅助流程

**步骤 1：数据概览**
- Prompt：生成数据概览代码
- LLM 输出：df.info(), df.describe(), df.shape
- 人工审核：✓ 正确

**步骤 2：缺失值**
- Prompt：生成缺失值统计代码
- LLM 输出：df.isnull().sum() / len(df)
- 人工审核：✓ 正确

**步骤 3：分布分析**
- Prompt：生成 amount 分布的直方图和统计量
- LLM 输出：histplot + 偏度峰度计算
- 人工审核：✓ 正确

**步骤 4：分组分析**
- Prompt：按 channel 分组统计 amount
- LLM 输出：groupby + agg
- 人工审核：发现 LLM 用了错误的聚合函数 → 修正

**步骤 5：时序分析**
- Prompt：按月交易量趋势
- LLM 输出：resample('M') + plot
- 人工审核：✓ 正确

**步骤 6：假设生成**
- Prompt：基于以上 EDA，列出 3 个值得深挖的假设
- LLM 输出：
  1. 某渠道金额异常高
  2. 月末交易量突增
  3. status 分布异常
- 人工验证：1 和 3 成立，2 是季节性

### 4. 效率对比

| 环节 | 人工时间 | LLM 辅助 | 加速 |
|------|---------|----------|------|
| 概览 | 10 分钟 | 3 分钟 | 3x |
| 缺失值 | 5 分钟 | 2 分钟 | 2.5x |
| 分布 | 20 分钟 | 5 分钟 | 4x |
| 分组 | 15 分钟 | 8 分钟（含修正） | 2x |
| 时序 | 15 分钟 | 5 分钟 | 3x |
| 假设 | 30 分钟 | 10 分钟 | 3x |
| **总计** | **95 分钟** | **33 分钟** | **2.9x** |

### 5. 教训
- LLM 代码生成有 5-10% 错误率，必须审核
- 假设生成有价值但需验证
- 敏感字段（account_id）要脱敏
- LLM 加速 3 倍，但不是"无人工"

## 四、今日小结

- LLM 四种用法：取数、代码、解释、假设
- 代码生成可信度最高，取数需审核
- 数据安全分级：公开/内部/敏感
- LLM 加速 3 倍，但仍需人工审核
- 核心能力不能丢，要能判断 AI 对错
